# Демонстрация «Цифрового профиля сотрудника» на Render

Этот репозиторий содержит интернет-демонстрацию версии 2.11.1. Для первого запуска нужны аккаунты GitHub и Render. Один веб-сервис обслуживает интерфейс и API по HTTPS, второй ресурс — отдельная PostgreSQL. Оба настроены на Free в одном регионе. На чистой базе создаются вымышленные сотрудники и вакансии.

## 1. Выберите репозиторий и ветку демонстрации

Исходники интернет-демонстрации находятся в отдельной ветке [akezhan96/digital_passport_emp → render-demo](https://github.com/akezhan96/digital_passport_emp/tree/render-demo). Для Render укажите именно эту ветку. В её корне находятся `render.yaml`, `Dockerfile`, `hosting`, `frontend` и `backend`. Ветка публичная. Логины общедоступны, пароли сервис сгенерирует при развёртывании. Рабочая база, резервные копии, `config.env` закрытого контура и архив образов для автономной поставки в репозиторий не входят.

## 2. Запустите стенд на Render

1. Войдите на [dashboard.render.com](https://dashboard.render.com/). Выберите рабочее пространство, в котором доступна бесплатная база PostgreSQL.
2. Нажмите **New → Blueprint**. Подключите GitHub и предоставьте Render доступ к репозиторию `akezhan96/digital_passport_emp`. При выборе разрешений достаточно доступа к одному репозиторию.
3. Выберите репозиторий, ветку **render-demo**, путь **render.yaml**. Название Blueprint, например `digital-profile-demo`.
4. В предварительном просмотре должны быть ровно два ресурса — веб-сервис **digital-profile-demo** и база **digital-profile-demo-db**, оба **Free**. Если предлагается платный тариф, вернитесь к выбору рабочего пространства. Render допускает одну бесплатную базу на пространство.
5. Нажмите **Deploy Blueprint** (в некоторых версиях интерфейса кнопка называется **Apply**). Откройте сам веб-сервис и дождитесь статуса **Live**. Скопируйте **фактический HTTPS-адрес** из его карточки. Это ссылка для заказчика.

База доступна веб-сервису по внутренней сети. Стенд не соединяется с локальной кадровой системой. [Инструкция Render по Blueprint](https://render.com/docs/infrastructure-as-code)

## 3. Войдите и проведите показ

В карточке **веб-сервиса** откройте **Environment**. Render генерирует разные пароли для двух аккаунтов. Главная кнопка входа в демоприложение принимает следующие логины:

| Для кого | Логин | Пароль в Environment |
|---|---|---|
| Ведущий показа, может редактировать учебные записи | `presenter` | `DEMO_ADMIN_PASSWORD` |
| Заказчик, просмотр и анализ | `customer` | `DEMO_VIEWER_PASSWORD` |

Для самостоятельного просмотра передайте заказчику ссылку и данные **customer**. `AUTH_SECRET` и `DATABASE_URL` используются внутренними службами. Не пересылайте заказчику скриншот раздела Environment.

Откройте «Структуру» и найдите «Подразделение 2». В карточке DEMO-001 откройте «Карьера» для показа контракта, звания и поощрения. Затем покажите DEMO-002 в разделе «Аналитика → В распоряжении», сформируйте резюме и попробуйте подбор по одной из трёх вакансий. Работают русский и казахский языки. Помощник с локальными моделями можно продемонстрировать на компьютере с автономной установкой. На интернет-стенде загрузка вложений отключена. Вводите только вымышленные сведения.

## 4. Чего ожидать от бесплатного тарифа

- После 15 минут без обращений веб-сервис засыпает. Первый запрос будит его примерно за минуту. Перед встречей заранее откройте ссылку.
- Изменения учебных записей сохраняются в PostgreSQL при перезапуске веб-сервиса. Бесплатная база имеет объём 1 ГБ и доступна 30 дней со дня создания. Отметьте дату окончания показа.
- Если ссылка показывает ошибку, в Render проверьте статус базы, затем **Logs** веб-сервиса. После исправления сборку можно повторить через **Manual Deploy → Deploy latest commit**. Для дальнейших обновлений вручную запускайте новый deploy после отправки изменений в ветку render-demo.

[Условия бесплатного тарифа Render](https://render.com/docs/free)
